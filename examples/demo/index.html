Raw WebMCP vs simple-webmcp — same capability

    
Left: what you’d write with document.modelContext.registerTool (schema + wrapper + lifecycle). Right: what you write with webmcp. Both register add_to_cart with productId: string enum + quantity: integer 1–10, but one keeps your function callable.

    

      

        
 Raw WebMCP — 22 lines manual

        
document.modelContext.registerTool({
  name: 'add_to_cart',
  description: 'Add product to cart',
  inputSchema: {
    type: 'object',
    properties: {
      productId: {
        type: 'string',
        enum: ['macbook','keyboard','mouse','monitor'],
        description: 'Product ID'
      },
      quantity: {
        type: 'integer',
        minimum: 1, maximum: 10,
        default: 1
      }
    },
    required: ['productId','quantity']
  },
  execute: ({productId, quantity}) =>
    addToCart({productId, quantity})
}, { signal });

        
You maintain inputSchema + wrapper + AbortSignal yourself. addToCart not callable as tool.

      

      

        
 simple-webmcp — 1 line function-first

        
import { webmcp } from 'simple-webmcp';
const addToCartTool = webmcp(addToCart, {
  description: 'Add product to cart',
  fields: {
    productId: {
      type: 'string',
      enum: ['macbook','keyboard','mouse','monitor'],
      description: 'Product ID'
    },
    quantity: { type: 'integer', minimum: 1, maximum: 10, default: 1 }
  }
});
// still callable:
await addToCartTool({productId:'keyboard', quantity:1});
// vanilla: await tool.register()
// React: const t = useWebMCP(addToCart, {description})


        
fields patches inferred schema; whole schema (Zod) wins. No wrapper, no inputSchema duplication.
